# TriCollect 三面球仓 v0.1.4

这是一个独立的微信小游戏候选工程。取可访问容器的顶部球到七格托盘，三同自动消除，外层清空后揭开内层。包含 TypeScript 完整源码、微信预构建产物、浏览器辅助预览、音效、测试及验证记录。没有服务器、账号系统或内购。

**当前状态：代码与自动化验证候选版；未在微信开发者工具或真实设备验收，不能作为已通过发布审核的版本。** AppID 与真实广告位尚未配置；浏览器模拟广告不证明真实广告有效。原文档 45 项是验收设计，不是本包自动测试数量。

## v0.1.4 斜上方束管与背景音乐

视角改为斜上方：保留所有非空后管的暗色轮廓、内壁和椭圆开口，前排管身有轻微斜向高差，组成同一个三角束。后管不绘制球、没有点击区域，也不加入选球列表或提示。空管消失后逐层露出仍沿用 v0.1.3 规则，21/28/36 管、300 秒与250ms转动不变。窄屏自动缩短管高，为纵深和面编号留出空间。

加入 `assets/ambience.wav`：程序原创的16秒五声音阶轻音循环，单声道22050Hz，无外部采样、音乐服务或新增依赖。顶部“声音：开/关”同时控制背景音乐和取球音效，偏好独立保存，跨新局和重启保持。首次用户手势后开始播放；暂停、后台、广告、结束与首页静音，主动继续后复用同一个播放器，不叠音。音频初始化、播放或异步失败只停用本次音乐，不阻塞游戏。

`npm run test:audio` 使用真实 HTMLAudioElement 验证文件解码、16秒循环边界、暂停恢复、偏好和重复进出。信号检查无削波，详见 `evidence/v0.1.4-audio-signal.json`。**未进行人工听测，未在微信开发者工具或真机试听**；轻柔程度、音量和设备静音键行为仍需实际试玩确认。微信音频接口依据官方类型声明检查，但不代替设备验收。

v0.1.3 存档规则版本保持兼容。内部视觉截图只供 QA，不上传 Library，也不包含在源码包中。

## v0.1.3 正面与管身迭代（规则保留）

默认增加到 21 管（63 球），另有 28 管（84 球）与 36 管（108 球），基础时长均保持 300 秒。静止时每个面最多显示 6、7、8 根前排管，珊瑚、翡翠、星蓝三个面都有编号。外壳不透明，观察窗只展示该管的球，饰边与几何纹样使用原生 Canvas 绘制。

三面共用一个三角格球仓。沿当前面的每条视线仅展示最近的非空管，并与外部连通洪泛集合求交；前管清空后，原位置后面的内管才出现。渲染、点击、辅助列表、提示第一步共用此可见规则，背面不能从列表偷选。转动采用约 250ms 的压缩、侧移、展开投影，过半切换显示面，不叠画背面球。期间不能取球，但可继续左右转；重复操作合并净转向，暂停/恢复保存最终请求面，重开清除旧转动。

规则版本升级为 `tricollect-2-frontfaces`。v0.1.2 及更早的未完成存档不能按新尺寸/可见规则继续，首页会提示版本不兼容；尚未选择新局时不会覆盖旧存档。开始新局后才写入新版本。

运行 `npm run test:visual` 可重跑三个面、内层露出、连续转向和 320×660 窄屏检查。`evidence/v0.1.3-visual-qa.json` 与本次截图来自 Chromium，不是微信开发者工具实测。300 个种子按实际面与 reducer 回放无广告获胜；这不等于人类 5 分钟平衡已验收。

## v0.1.2 可玩性修复（保留回归）

启动时用两段短采样校准 `wx.getPerformance().now()` 的实际单位（毫秒或微秒），不再固定除以 1000。活动计时仍完全使用校准后的单调时钟；墙钟仅用于启动校准和停滞诊断，不用于扣除局内时间。没有可用、持续前进的时钟时明确显示错误，不启动一个停表且锁输入的局面。控制台会输出本次校准单位，便于真实微信复查。

原 v0.1.1 bundle 在输入“毫秒”语义时实际复现：10 秒只扣 10ms，第一次取球后 1 秒仍不能再次取球；输入官方“微秒”语义时正常。此证据证明条件性故障路径，**没有证明用户运行时的时钟单位；用户现已确认是在微信开发者工具测试，具体版本与返回值尚未取得**。官方类型仍声明微秒，故用实测校准兼容两类语义，不直接猜平台。

帧循环在工作前安排下一帧，单次渲染异常转为可见暂停，不再永久停止 RAF；音效异常不打断规则结算。v0.1.2 曾改为同步切面；v0.1.3 按新反馈改为短动画。底部仅保留左右转、撤销、提示，暂停放在顶部；直接点亮圈顶部球为主，遮挡目标才展开左上“选球”面板。

动画补充核验直接执行微信 bundle，并使用真实宿主定时器与独立 `Date.now()` 限时：完整开场约 950ms，跳过立即 ready，取球转移约 240ms 后飞行球消失、剩余球稳定且可再次取球。冻结时钟在启动时被拒绝；运行中停滞会在约 1.5 秒后转为可见暂停并可返回首页，不会无提示地一直慢放。本版复测详见 `evidence/v0.1.3-animation-wallclock.json`。

回归覆盖两种时钟语义、真实等待约 10 秒、连续取球、三个预设完整局、连续转向、暂停恢复、冻结时钟与单帧/音频异常。实际微信工具/真机仍待用户复验，不能以这些模拟与浏览器结果宣称真机已修好。

## 直接导入微信开发者工具

1. 解压本包，打开 `dist/wechat`，里面有 `game.js`、`game.json`、`project.config.json` 和音效。无需先安装 Node 或 npm。
2. 在微信开发者工具选择导入项目，目录指向 `dist/wechat`，项目类型为**小游戏**。配置中的 `touristappid` 仅为占位，若工具不支持游客小游戏，请填入自己的小游戏 AppID；不要填普通小程序 AppID。无需把密码发给任何人。
3. 基础库配置暂为 `3.7.1`，使用工具可用的兼容版本并记录实际版本；本环境没有微信开发者工具，未实测该版本。首次编译后应出现“三面球仓”首页。没有页面路由或 WebView。
4. 点“初见”，等待或跳过落球开场，再主动点击“开始”。左右按钮或横滑旋转 120°；点击带亮圈的顶部球。左上“选球”仅列当前正面的顶部球，背面和被遮挡内管不列出。暂停遮住棋盘。
5. 按 `docs/DEVICE-CHECKLIST.md` 做前后台、触摸、音效、时间、存档和性能验收。扫码真机预览需要你账号的实际权限。

## 从源码构建

已在 Node `24.19.0`、npm `11.9.0`、Linux x64 构建。使用锁文件安装：

```sh
npm ci
npm run build
npm run typecheck
npm test
npm run verify:seeds
npm run format:check
```

`npm test` 包含微信预构建入口的 mock runtime 冒烟测试，因此修改源码后先构建。

```sh
npm run preview
```

浏览器打开 `http://127.0.0.1:4173`。该预览共用规则和呈现代码，但它是**开发辅助页面**，不是微信包或发布证明。这里的续时按钮使用醒目标记的模拟确认框，取消不发奖。

浏览器交互测试需本机 Chromium：

```sh
# Linux 示例；Windows/macOS 需指向自己的 Chrome/Chromium 可执行文件
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

脚本会启动并关闭本地预览服务，输出 `evidence/e2e.json`。不连接远程测试站点。

## 参数与环境

- `src/config.ts`：集中规则配置。基础时间统一 300 秒，槽 7 格，三同消除。加时暂定每次 30 秒、每局最多 2 次；仅超时页自愿请求。撤销与可靠提示免费，额度待试玩确定。
- 预设：初见 21 管 / 63 球 / 5 类；探索 28 管 / 84 球 / 6 类；深入 36 管 / 108 球 / 7 类。全部为机械与体验候选，尚无真实人类 5 分钟平衡承诺。
- `config/platform.example.json`：复制为 `config/platform.local.json`，填入 AppID 与激励视频广告位 ID，再构建。该本地配置被排除在交付包之外；字段不是账号密码。
- 环境隔离：微信构建始终走真实适配器，广告位空时明确不可用；浏览器开发构建走模拟适配器；Node 测试通过注入 mock 控制回调。`environment` 字段仅允许 `prod` 的微信配置，不会启用模拟发奖。
- 初始种子来自预设；结算后“再来一局”递增种子，生成仍逐局通过真实 reducer 验证。详细回放证据见 `evidence/seeds.json`，共测试 300 个实际种子。

## 源码布局

| 路径                  | 职责                                             |
| --------------------- | ------------------------------------------------ |
| `src/core`            | 洪泛暴露、确定性取球/消除、生成与预算求解        |
| `src/controller.ts`   | 单调计时、状态机、撤销、奖励账本、生命周期       |
| `src/render/scene.ts` | 三角格正面遮挡、Canvas 管身与短转动、触摸与 UI   |
| `src/platform`        | 存储校验/备份、微信奖励适配、独立开发模拟        |
| `src/wechat.ts`       | 原生 `wx.createCanvas`、触摸、音频、存储和前后台 |
| `src/browser.ts`      | 浏览器辅助预览与测试观察接口，不进入微信包       |
| `dist/wechat`         | 可导入小游戏候选产物                             |
| `tests`, `evidence`   | 可重跑测试及本次实际执行记录                     |

采用轻量 Canvas 风格化空间转动与正面视线遮挡；后管只显示暗色外壳和开口，不使用外部素材或重型引擎。三角格坐标与六邻接洪泛决定内层访问，透明像素不决定规则。可选列表只补充当前正面的触摸入口，不能泄露其他面的球。

## 规则与保存边界

每个动作原子完成顶部弹出、三同、计分、暴露和终局，再播放动画。计时在输入前更新：到零拒绝输入，零前提交的最后一组可正常获胜。取球动画、短转动、暂停、后台、广告停表；旋转免费，转动时不能取球。微信时钟在启动时测定单位后统一到毫秒；真机仍需进行 10 秒秒表对照。

本地保存棋盘、剩余时间、历史、规则版本、奖励账本和视角。采用临时写入校验、主记录与上一有效备份；损坏或未知版本不静默补局。退出最多可能丢失最近一个检查点（活动期间每秒），不会把墙钟离线时间算进本局。撤销只恢复规则快照与分数，不退时间或奖励。

广告仅 `onClose.isEnded === true` 可兑付一次，与 session/request 绑定；load/show/onShow 均不发奖。取消和错误回到原超时选择。120 秒无回调会结束等待并停用本次进程广告，避免迟到回调污染新请求。恢复未决请求不补发权益。本地校验不是防作弊服务；存储可被用户清除。
