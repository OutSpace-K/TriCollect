# v0.1.25 微信声音与手机触控

## 问题与修复

微信 `InnerAudioContext.play()` 返回 `void`，原状态机在调用后立即记为正在播放。如果首次自动播放被静默阻止，首次触摸也不会重试。这次区分等待播放与已播放，等待 `onPlay` 或浏览器的播放 Promise 确认；未确认或错误后只在手势重试，不每帧循环调用。

微信端同时设置全局 `setInnerAudioOption({ obeyMuteSwitch: false })` 和兼容旧版本的实例属性。游戏内声音偏好保持不变。暂停、广告、结算、后台与系统音频中断均停止音乐；晚到的 `onPlay` 不得绕过这些限制。系统中断结束后按当前前后台、声音开关和游戏阶段恢复。音频错误在控制台保留 `TriCollect audio` 警告以便真机排查。

这解释了代码中的可复现故障路径，尚未证明是用户设备上唯一的无声原因。媒体音量、蓝牙/耳机输出、微信或基础库问题仍需实机确认；没有重新生成或替换音乐素材。

手机画面减少瓶仓空白纵深，缩小左右预留并略微上移绘制区，扩大实际球体，保留三角束绕固定中心旋转、相贴固定槽位和管壁间隙。三个代表性屏幕的计算结果见 `evidence/v0.1.25-ball-sizes.json`，不是设备实测数据。

点击区域至少按 44 屏幕像素直径设置，并在矮屏缩放后换算。真实顶球优先；容错区域相交时选距离最近的合法顶球，而不是最后绘制的目标。触及下层或隐藏球时，不使用容错区域代取其他球。因此 44 像素是容错范围，不是每个球都有互不遮挡的完整 44 像素按钮。横滑和轻点使用屏幕像素距离，避免矮屏缩放缩小手指抖动容许值；多触点起始与取消触摸不会触发轻点。

玩法、难度生成、300 秒有效时间、免费撤销、存档兼容、广告奖励和公开仓库权限未改动。

## 验证范围

- TypeScript、两端构建、Prettier 与 diff 空白检查通过。最终源码全套 130 项测试通过（`node --import tsx --test --test-concurrency=1 tests/*.test.ts`）；`tsx` CLI 在宿主中因 IPC 限制不可运行，使用相同测试引擎的 Node 入口完成。
- `node --import tsx scripts/verify-seeds.ts` 验证三档共 300 个种子，见证路线均无广告获胜并保持球身份守恒。
- 音频单测覆盖原生事件、浏览器 Promise、静默失败、晚到事件、静音及系统中断。
- 微信构建入口 mock 覆盖原生播放事件、首次触摸重试及前后台/中断/静音状态。
- 交互回归覆盖小屏近点、直接点下层/隐藏球、连续点击锁和重叠容错区域。
- 独立离屏渲染真实 Scene 与背景，检查四种屏幕、三种难度、三面、旋转中间帧及内层/低位球，共 456 帧。29,031 次下层/隐藏球中心检查未误取，15,340 次顶部/边缘检查符合预期。截图人工检查未见球、管裁切或底部按钮遮挡；环境缺少中文字体，文字方框不用于字体验收。
- Chromium 浏览器启动因宿主 Unix socket 限制失败，本次没有浏览器端到端或浏览器解码通过结论。离屏渲染不是对浏览器验证的替代宣称。
- 未运行真实微信开发者工具，未试听 iOS/Android 体验版。须按 `DEVICE-CHECKLIST.md` 的 v0.1.25 项确认，尤其是 iOS 静音开关、首触、来电/广告返回及低位球触控。

## 更新体验版

仓库中的 `dist/wechat` 是本次预构建包。拉取最新代码后，如果使用自己的 AppID/广告位，保持 `config/platform.local.json` 并重新执行构建；不能把游客占位 AppID 当作真实配置。通过用户自己的微信开发者工具上传体验版并扫码确认版本。此次源码交付不表示已代为上传、审核或正式发布。
